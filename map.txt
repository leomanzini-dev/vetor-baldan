!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!
  ATENCAO — COMPORTAMENTO DO WHATSAPP (ZAPPER)
!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!

  O bot do WhatsApp simula comportamento HUMANO para nao
  parecer bot. Isso e INTENCIONAL e NAO deve ser removido.

  1. DIGITANDO: ao receber /baldan, o bot ativa o status
     "composing" (digitando...) ANTES de chamar a IA.
     O usuario ve "digitando..." enquanto a resposta e
     gerada. Arquivo: zapper/script/message-handler.js

  2. DELAY DE 2 SEGUNDOS: depois que a IA gera a resposta,
     o bot espera mais 2s AINDA DIGITANDO antes de enviar.
     Isso garante que o tempo total pareca natural (uma
     pessoa lendo, pensando e digitando). Sem esse delay,
     respostas rapidas da IA chegariam instantaneamente
     apos o "digitando..." aparecer, o que entrega que e
     um bot.

  3. PAUSED: depois de enviar, o bot desativa o status
     (sendPresenceUpdate "paused"). O "digitando..." some.

  Fluxo completo:
    usuario manda /baldan <pergunta>
    → bot ativa "composing" (digitando...)
    → bot chama POST /api/ai/chat (IA pensa, 3-15s)
    → bot espera +2s (ainda digitando)
    → bot envia a resposta
    → bot desativa "composing" (paused)

  NAO REMOVER o delay nem o composing. Se a resposta da IA
  ficar mais lenta no futuro, o delay de 2s pode ser
  reduzido, mas nunca zerado.

==============================
CAMADA DE DADOS
==============================

  Nao ha banco de dados. O backend gera tudo em memoria na subida usando um
  PRNG deterministico (mulberry32, seed 20240914). Reiniciar o backend recria
  o portfolio identico. O snapshot.mjs exporta os dados como JSON estatico
  para frontend/public/data/, permitindo publicar o front no GitHub Pages sem
  servidor Node.

  Em runtime, o frontend le os JSONs estaticos via fetch e faz filtragem,
  paginacao e priorizacao client-side. Nao ha escrita, login real nem sessao.

  Os stores Zustand (localStorage) persistem:
    - persona ativa
    - pesos de priorizacao e presets customizados
    - parametros de capacidade
    - escala TRL editada
    - tema light/dark
    - historico de navegacao do Sentinela

==============================
INTELIGENCIA ARTIFICIAL
==============================

  RAG hibrido em 2 etapas, sem banco vetorial:

  Etapa 1 — Router: recebe a pergunta, consulta o catalogo de 7 sumarios e
  escolhe semanticamente quais sao relevantes (via IA).

  Etapa 2 — Responder: carrega os sumarios selecionados (texto estruturado
  gerado em tempo real a partir dos dados em memoria do backend), monta o
  prompt com o contexto e gera a resposta final.

  Fallback do cliente: Gemini tenta 3x; se falhar, Arcee tenta 3x; se
  ainda falhar, retorna erro. Fail-fast em 4xx (auth/schema) — nao repete
  o mesmo provider se o erro for deterministico. Timeout de 30s por chamada.

  Variaveis de ambiente (.env na raiz):
    GEMINI_API_KEY       chave da API Gemini
    GEMINI_MODEL         modelo (padrao: gemini-2.5-flash)
    ARCEE_API_KEY        chave da API Arcee
    ARCEE_BASE_URL       base URL (padrao: https://api.arcee.ai/api/v1)
    ARCEE_MODEL          modelo (padrao: Trinity-Large-Thinking)

  7 sumarios disponiveis:
    VISAO_GERAL          KPIs, saude, verticais, funil, criticos, top prioridade
    PRIORIZACAO          ranking, faixas, top 10, media das 8 lentes
    MATURIDADE           distribuicao TRL, roadmap, proximos a escalar
    EXECUCAO             SPI/CPI, capacidade, sobrecarga da equipe
    PROJETOS             catalogo completo dos 180 projetos
    EQUIPE               29 membros por perfil, carga, vertical
    SEGURANCA            descricao do Security Guard

==============================
SISTEMA DE PERFIS / PERSONAS
==============================

  5 perfis sem autenticacao real (troca via seletor na topbar, persiste em localStorage):

  diretoria      visao total, aprova gates, edita parametros
  pmo            governanca cross, edita TRL e pesos
  area           gestao da propria vertical
  controladoria  read-only financeiro
  executor       micro-etapas no app mobile (PhoneFrame)

  O Sentinela audita cada navegacao e classifica autorizado/bloqueado
  usando a mesma matriz de permissoes de config/permissions.ts. Acessivel
  pelo icone na topbar (ao lado do sino) ou pelo item "Sentinela" no menu
  lateral (rota /sentinela, so serve de gatilho para abrir/fechar o overlay
  global controlado por sentinelaStore — nao renderiza conteudo proprio).

==============================
PRIORIZACAO (MOTOR)
==============================

  8 lentes fixas avaliam cada projeto (score 0-100):
    alinhamento_estrategico, potencial_mercado, viabilidade_tecnica,
    impacto_financeiro, risco, capacidade_execucao, inovacao, regulatorio_esg

  4 presets de pesos prontos: Padrao Baldan, Foco Financeiro, Foco Estrategico, ESG & Regulatorio.
  O usuario pode criar lentes customizadas e presets proprios.
  Recalculo e reordenamento acontecem em tempo real ao mover os sliders.

SECURITY GUARD
==============================

  Overlay fullscreen dark (position:fixed, z-index sobre tudo) na rota
  /seguranca. Sem link no menu lateral (o item de menu agora abre o
  Sentinela, ver SISTEMA DE PERFIS / PERSONAS) — ainda acessivel por URL
  direta. Fecha com botao ou Esc.

  Dados 100% mocados via PRNG deterministico (mulberry32, seed 20240914).
  Refresh automatico a cada 8 segundos com seed incremental, simulando
  novos eventos em tempo real. Sem backend.

  Tres tipos de ator:
    USER      #22c55e (verde)   — acesso autenticado
    BOT       #ff2f4f (vermelho) — requisicao sem sessao
    SSH_TRY   #a855f7 (roxo)    — tentativa de acesso SSH

  Mesma arquitetura visual do Spendio Guard.

==============================
WHATSAPP IA (ZAPPER)
==============================

  Bot de WhatsApp via Baileys (WhatsApp Web). Roda separado do backend.

  Estrutura:
    zapper/
      package.json         Baileys + qrcode
      start.js             entry point: carrega .env da raiz e local, inicia main()
      script/
        index.js           orquestrador: control-server primeiro, depois bot
        bot.js             conexao WhatsApp, QR code via qrcode lib, reconexao automatica
        bridge-state.js    estado compartilhado (status, qr data URL, jid)
        control-server.js  HTTP na porta 3031: /health, /session (com QR)
        message-handler.js filtra mensagens, so responde /baldan, chama POST /api/ai/chat

  Comando: /baldan <pergunta>
    - Mensagem sem /baldan: ignorada silenciosamente
    - /baldan sozinho: instrucoes de uso
    - /baldan <texto>: chama a IA, responde com a resposta + raciocinio em *negrito*

    npm run zapper        (ou cd zapper && npm start)
